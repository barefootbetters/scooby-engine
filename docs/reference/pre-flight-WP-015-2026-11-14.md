## After execution — lessons learned

**Lesson: a size guard is a claim about the data, so check it against the data.** The 4,096-pixel side cap was a guess, and the all-cels check caught it on the first run (two 400 × 5,000+ cels). Hashing every cel, not just backgrounds, is what found it.

**Lesson: stage named files in a shared checkout.** `C:\dev\scummvm` is one working tree that several sessions use. `git add engines/scooby` picked up another session's uncommitted detection edits. Run `git status` and stage files by name before committing there.

**Lesson: start `scummvm.exe` directly from PowerShell.** Start it with `C:\msys64\ucrt64\bin` on `PATH`, and watch the `--logfile` for the expected line. That is more reliable than wrapping it in MSYS2 `bash -l`, which started late under load in WP-014.

**Scope note:** the lock held for this WP's own changes. The fork commit also carries the detection entry described in the Result. Integration §3 documents it through PR #46. Screenshots went to Jeff, not into git. The ISOs were dismounted afterwards.
