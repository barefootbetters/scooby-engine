## After execution — lessons learned

**Lesson: read which coordinate the claim's insertion sorts by, not just that it sorts.** Each of KST's marker arrays (`0x41A970`) is kept sorted ascending by the placement's **y**, with the x in a parallel array; the knights' x is read 40 less (`0x45EE50`), the gang entering from off the left. A first pass sorted by x and stored y alongside — and the reference, written the same way, matched the engine zero-differ while both misread the trace. Re-reading the decompile (the compare is `param_1 < *pfVar8` where `param_1` is the y, and `0x419110` later reads the knight's y from the bench-end array) showed the key is y. Both sides were fixed to y, the knights' x to 40 less, and bench-floor to y only, before anything shipped. A line-for-line match proves the engine equals the reference; it does not prove either is faithful — only an independent reading of the trace does that.

**Lesson: a timed set piece's check scopes to its deterministic surface.** KST's tick is `rand()`-and-frame-counter driven (knights spawn on a `rand() % 0x48 + 0x24` timer, a finished round plays a random `Correct<n>` line). The check proves what a static read of the art and the binary fully determines — the class, the markers, the sprites, the quota by level, the clips, the exit — and the live run confirms the serving loop and the dining-room exit, rather than asserting the timing tick-exact. The counter's live value (`(game+0xAC)+0x30`) is set but not asserted.

**Lesson: an eased approach never reaches its target.** The knights' walk, modelled as `x += (target − x) × k`, asymptotes toward the seat and never satisfies `x ≥ target`, so a knight never arrives, never is served, and the room never exits. The fix arrives within a small threshold of the target. The deterministic check never exercised the loop, so only the live run caught it.

**Lesson: KST is Phantom's Pie Noon, not a shared class.** The asserts in `enter` still read "...specified in Pie Noon", but the two titles share no room name; it is a separate class (`0x419700`) with the same framework, not the shared one Brad's three levels or the armory and its slide are. No split, and no WP-055 reuse.
