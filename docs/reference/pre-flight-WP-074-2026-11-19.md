## After execution — lessons learned

**Lesson: read the string bytes, not Ghidra's symbol labels — and confirm against the disc.** The maze's music and nine unicycle clips are `Hedge_Maze.Music` and `Hedge_Maze.Unicycle_*` with a **dot**; Ghidra names the symbols `s_Hedge_Maze_Unicycle_*`, underscoring the dot. A first pass used the underscored labels; the reference and the engine then agreed on "found 0" for every clip while both were wrong — exactly the WP-073 failure mode (a line-for-line match proves engine == reference, not that either is faithful). Reading the disc's sound index showed the clips exist under the dotted names, and `StrAt` on the string bytes confirmed the dots. The fix: use the dotted names, which resolve and play. An independent read of the disc, not just the diff, is what caught it.

**Lesson: a table with no independent source is derived mechanically, not hand-copied.** The maze's per-level cell masks are written in `enter` as a run of immediate stores — code constants, not a data table the art or sound index supplies, so there is no independent source to check a hand-transcription against. Both the reference and the engine must carry the table, which reintroduces the shared-misreading risk. The mitigation: a throwaway parser derives the tables from Ghidra's decompile and emits both the Python and the C++, so the two carry the same constants by construction; the decompile (the disassembler's own register-resolved output) is the single authority, and only the table's *meaning* — the `Y + X*10` index and the bit per direction — is read by hand, from the overlay/exit tests and the move handlers, independent of the values.

**Lesson: a voice line's id is a prefix, not a clip name.** The idle `Hedge_Maze.240A_` lines ship under the id plus a speaker suffix (`…240A_1_SHAGGY`), so an exact `findClip` misses them. The check tests them with a new `Sound::hasClipPrefix`; that also surfaced that the exe references `240A2_` (not shipped) while `240A3_` ships (not referenced). The exact-match `Sound::play` the tick uses is a no-op for these lines live — the original resolves the speaker; the fork does not, for this room.

**Lesson: keep the pair together.** `ROOM_Hedge_Maze` and `ROOM_Maze_Map` are one packet: the map is the maze map item's close-up, reached from inside the maze, and its markers jump to the maze rooms. They are meaningless apart, so they were not split — the later group-7 rooms remain separate packets.
