## After execution — lessons learned

**Lesson: a check's wait loop clears its result before it starts.** The helper that waited for the room to change tested a result left from the last wait, and returned it without ticking. The engine's own log had the right movies; the check's line didn't.

**Lesson: say what a field does only once it's traced.** The class sets the door's `+0x70` to the screwdriver. The live run showed the fork's cursor ignores it on a requires object, and the original's use of it isn't traced, so the docs name the field rather than call it a rollover.

**Scope note:** one fork commit of 7 files staged by name: the room and its check in new files, a factory line, the module entries, the check's declaration and its call.
