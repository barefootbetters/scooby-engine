## After execution — lessons learned

**Lesson: a class that keeps a clickable doesn't change how it's built.** The original's classes build such clickables with the same call as the default path, so their depth still comes from `priority=`. The fork's claim sets the claim's depth, which is 0 unless the class gives one. A clickable a class only needs to find is best left to the default path and found by name.

**Lesson: an unclaimed neighbour caught what the reference shared.** The reference had the same wrong depth for the claimed hotspots as the code, so they matched. Only hotspot 3, which goes through the default path, disagreed, and the trace settled it.

**Lesson: a scene's done flag can be kept by the class.** `0x40B400` sets a flag as the scene ends, in the base tick. The class watches for its scene to end in its own tick, which comes right after, so the drop starts on the same tick as in the original.

**Scope note:** one fork commit of 5 files staged by name. Besides the factory line and the module entry, no shared file changed.
