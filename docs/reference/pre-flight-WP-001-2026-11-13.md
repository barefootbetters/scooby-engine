## After execution — lessons learned

**Lesson: a table's size should come from the parser, not from where the next readable thing appears.** WP-003 sized the object table by eye. The bytes after 453 `u32` looked like a continuation of the table, because a name count and the first room names start with small integers. The engine's constructor reads count, array, count, array, count, records. One look at the parse order would have placed every later structure correctly. For any header table, find the code or the count that bounds it before documenting it.

**Lesson (repeat): write the pre-flight before the first probe.** WP-002 recorded the same lesson and this session repeated the miss. A session started from a brief should write this file first. The pre-flight template could say so in its header, so a brief-started session sees it before it starts work.
