## After execution — lessons learned

**Lesson: confirm a claim before working on it.** This WP's table came from a full duplicate of WP-023. Both sessions sent claim messages that sat queued while the other was busy, so neither saw the other's in time. Before tracing, fetch `main` and the fork, and wait for an answer to the claim.

**Lesson: a new state breaks checks that assumed the old one.** WP-023's check had always used room 0 and waited for the toolbar to open. Hiding broke both assumptions in Phantom, whose room 0 never builds the toolbar. The engine was right both times; the check needed to know about the new state.
