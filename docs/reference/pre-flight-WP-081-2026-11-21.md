## After execution — lessons learned

- **The scope split was the packet's main decision.** The last group-8 room,
  `ROOM_P30_WFR`, turned out to be the Wizard's Rule Room — a 1022-line
  floating-point spinner/potion minigame, the game's largest class and its own
  audit sub-bullet. It was split to WP-082 rather than crammed into this packet,
  which keeps the fork PR and the trace of the two tractable rooms reviewable.
- **The strcmp polarity (the WP-077 trap) was pinned empirically.** The veranda's
  `arrive` guards the room left with `0x433460`, not `0x433360`; decompiling both
  showed `0x433360` true on **equal** and `0x433460` true on **not equal**, so the
  veranda plays its intro when `from != "ROOM_Big_Head"`. Never read a
  string-compare's polarity from the branch alone.
- **One session traced; verification was against the fork's own siblings.** Rather
  than a second-session trace, each engine call was mapped against code already in
  the fork and tested — the dining room's accusation (`meetSuspect`, the clue at
  game vtable `+0x44`, `act("GIVES")`, the `ROOM_Suspect_Chooser` /
  `Global.Thank_You_` exit), the post office's `arrive`→`setOpening`, and the
  below-balcony door's save/load — and the ambiguous helpers (`0x432120` the
  sprite's hidden byte, `0x40a930`/`0x40a870` the suspect queries) decompiled
  directly. Engine == reference passed line for line.
- **The check's one correction (the WP-074 anim-vs-clip trap again).**
  `Global.Thank_You_` is a scene (the accusation the dining room and arenas also
  use), not a sound clip, so a `hasClipPrefix` probe read "0" of a name that is
  right. It is named, not probed — the live log confirms it starts as a scene and
  leaves to `ROOM_Suspect_Chooser`.
- **The from-WFR arming path waits on WP-082.** The wizard's clue, his GIVES pose
  and the armed accusation only fire on the return from `ROOM_P30_WFR`, which is
  not yet ported; the self-test verifies the wiring, and the identical
  `Global.Thank_You_` → `ROOM_Suspect_Chooser` idiom is exercised live by the
  dining room (WP-063) and the arenas (WP-069).
- The Ghidra "warm project holds Showdown" hazard (WP-076) held again: Phantom was
  re-decompiled from the throwaway scratchpad project, read-only; the committed
  project was left untouched.
