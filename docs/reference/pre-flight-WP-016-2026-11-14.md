## Doc-vs-tree cross-check

- **`probe_art.py` floors** 5- and 6-bit channels (`v × 255 // 31`) and composites in 8-bit RGBA. The original rounds and blends on the 565 screen. The probe's PNGs stay a visual reference. Exactness is checked against a 565 model that uses the probe's tree code. The tgifile-art note "expands each nibble … through a table" gets the table values.
- **Draw method.** The original draws front to back with occlusion and then blends queued alpha regions back to front (`0x439C00`, `0x438660`). This WP paints back to front. For opaque pixels the two are the same. For translucent pixels they match as long as the blends happen in the same back-to-front order, which they do.

## After execution — lessons learned

**Lesson: read the blitter before trusting a reference.** The probe's RGBA renders looked right, but the original rounds its 5- and 6-bit expansion where the probe floors. Exact matching needed the decompiled blend and the dumped tables. Model the target's arithmetic, not a plausible one.

**Lesson: a hash map's values move.** The first draft of `RoomRenderer` kept raw pointers to object blocks stored in a `HashMap`, and a rehash would leave them dangling. Shared pointers fixed it before the first build. Watch for this wherever blocks are cached.

**Lesson: staging by name in the shared fork checkout worked.** `git status` before staging showed only this WP's seven files, and they were staged explicitly (WP-015 lesson).

**Scope note:** the lock held. One fork commit. The ISOs were dismounted afterwards, and the screenshots and probe renders stayed in the scratchpad.
